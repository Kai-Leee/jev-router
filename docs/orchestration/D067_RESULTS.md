# D067 — 토큰 상한 해제 후 네 조건 병렬 실측

2026-10-11. 조건별·누적 토큰 상한을 해제한 뒤 기존 `openapi_python_client` 생성 과제로 네 조건을 실제 병렬 실행했다. **Claude 기준선과 Jev 두 조건은 완료했고, Jev 전체 판단 조건은 공개 검사 실패 뒤 수리 요청이 모델 입력 한도로 거절됐다.** 네 후보 모두 독립 63개 검사는 통과했다. 독립 검사 통과가 공개 검사 실패를 무효화하지 않는다.

근거: [원시 결과](../../benchmark-runs/d067-comparison-01/result.json), [최종 분석 02](../../benchmark-runs/d067-analysis-02.json), [사전 프로토콜](D067_EXPERIMENT.md), [실제 작업 배정](D067_TASK_ASSIGNMENTS.md), [구현·검증](D067_IMPLEMENTATION.md). 분석 01과 실행 원본은 보존했다. 02는 HTTP 실패 원인과 종료 후 환불 정산을 추가했으며 실패한 시도를 성공으로 바꾸지 않았다.

## Jev 수리 중단 원인과 기록 결함

`jev_all` 공개 실패는 T.R10.02·T.R10.03의 Google 형식 docstring 구역 사이 빈 줄 요구였다. 그 외 공개 83개와 독립 63개가 통과했다. 숨김 검사 세부사항은 열람하거나 수리 입력으로 전달하지 않았다.

수리 요청 `jev-0056`의 실제 직렬화 JSON은 **188,240바이트**다. 보기 좋게 저장한 요청 파일 251,877바이트와 구별한다. 로컬 240,000바이트 검사는 통과했지만 서버는 `HTTP 400 / model_input_limit`을 반환했다. state 186,706바이트 중 failure가 102,464바이트였고 공개·로컬 검증 기록이 크게 포함됐다. 정확한 모델 입력 토큰 수는 응답에 없으므로 바이트에서 추정해 채우지 않았다. [공식 문서](https://jev-ai.pro/docs#models-limits)도 API 본문 제한과 모델 문맥 제한을 구분한다.

로컬 설계에서 발견한 결함은 두 가지다.

1. 입력 바이트 제한과 예약 65,536토큰은 모델 문맥 적합성 검사가 아니다. 수리 선택에 불필요한 전체 검증 기록까지 보내는 구조를 이 제한이 막지 못했다.
2. 하위 HTTP 계층은 확정 실패를 기록했지만 상위 어댑터는 `submitted && response === null`이면 불확실로 올렸다. 최종 중단 코드도 수리 HTTP400 대신 이전 공개 검사의 `ARTIFACT_CHECK_NOT_PASSED`를 보여줬다. 응답 실패·추론 사용량 미상·장부 미정산을 한 상태로 합친 보고 결함이다.

이 조건에서 **Jev 수리 답변·수리 선택·수리 작업자 실행은 모두 0**이다. 이름에 수리가 포함된 조건을 실행했다는 사실을 자동 수리 성공으로 해석하지 않는다. 기존 결과·후보는 수정하지 않았고 자동 재요청도 하지 않았다.

별도 무모델 입력 구성 비교에서는 원문 질문·후보·요구사항과 공개 85개 case를 보존하면서 전체 실행 envelope를 필요한 검사 요약으로 바꾼 A가 **113,230바이트(원본 대비 39.8481% 감소)**, 여기에 중복 인터페이스를 보존된 단위 참조로 바꾼 B가 **99,951바이트(46.9024% 감소)**였다. 분모는 동일 원본 188,240바이트다. [측정·보존 검사 JSON](../../benchmark-runs/d067-review/repair-failure-analysis-01.json)과 위 진단의 재현 코드를 따른다. 이는 바이트와 구조 보존 검사이며 **실제 모델 수락·토큰 절감·판단 품질·속도 효과는 미측정**이다. 생산 입력이나 원본 후보에 적용하지 않았다.

## 남은 일과 부수 효과

다음 구현 우선순위는 실패한 검사·담당자·필수 revision·관련 진단만 수리 질문에 연결하는 입력 구성, 확정 HTTP 실패와 미정산 상태를 분리하는 오류 전파, 첫 묶음 쏠림과 장부 시작 대기 개선이다. 입력을 줄인 후보는 원본과 다른 조건이므로 별도 명세·무모델 검사 후 새 실험으로 비교해야 한다. Jev 자동 수리의 성공률·효율, 자유 후보 생성, 반복 표본의 안정성은 아직 검증되지 않았다.

네 조건·채점·모니터 프로세스는 모두 종료했다. 시작/종료 전체 ID 기준 컨테이너 22개 동일, 신규 잔류 0, 기존 실행 컨테이너 3개는 그대로다. [정리 검사 02](../../benchmark-runs/d067-preflight/container-cleanup-audit-02.json). 첫 정리 검사는 전체 ID와 축약 ID를 비교해 모두 신규로 잘못 분류했으므로 보존 후 같은 ID 형식으로 정정했다. 실제 컨테이너 삭제는 이 점검에서 하지 않았다.

생성 후보·원시 요청/응답·로그·사전 검사/임시 설정과 소스·문서 변경은 로컬에 보존하며 미커밋이다. 기존 Personal OS/Vault·이전 실험은 변경하지 않았다. 커밋·푸시·전역 스킬 설치는 하지 않았다.
