# D068 — 수리 입력·원인·재호출 범위 수정 후 Jev 전체 판단

2026-10-11 KST. 최신 사용자 요청으로 세 수정 작업을 병렬 수행한 뒤 **새 `jev_all` 한 조건을 실제 실행**한다. [역할](../agents/D068_PARALLEL.md), [이전 실측](D067_RESULTS.md), [직전 진단](../../benchmark-runs/d067-review/repair-failure-analysis-01.md). 기존 D066/D067 산출물·후보·소스 snapshot·실패 기록은 보존한다. 이번 폴더만 새로 만들며 종료 시도를 이어 쓰지 않는다.

## 목적과 변경

1. 수리 판단에 필요한 모든 공개 case와 오류·미실행 구분, 원문 요구사항·선택지·artifact/version/environment 연결은 유지한다. 반복 설치 출력·revision/runtime 묶음·복원 가능한 인터페이스를 투영으로 줄인다. 전송 바이트와 실제 모델 입력 토큰을 별도로 측정한다.
2. 확정 HTTP 400 등을 성공 응답 부재만으로 uncertain으로 바꾸지 않는다. structured terminal cause로 stage/code/HTTP 상태/정제한 category를 최종 결과에 전달하고 앞선 공개 실패를 별도로 보존한다. 전송 불확실성과 정산 미확인은 유지하며 자동 재시도는 0이다.
3. 미실행 검사만을 실패 소유자 선정 근거로 쓰지 않는다. 공개 오류에서 실제 파일·산출물에 연결 가능한 fixture blocker와 관측한 실패를 구분하고 필요한 수리 후보만 제공한다. 불명확한 경우를 숨기지 않는다. 선택한 수리 작업 후 공개 검사 전체를 재실행한다.

## 고정 조건과 실행 범위

같은 E2E-SWE `openapi_python_client` 공개 과제, 원문 요구사항 80개, D066 source-only catalog의 21단위·22산출물·38파일을 재사용한다. 생성 prompt/schema와 생성에 영향을 주는 소스는 동일성 검사한다. 새 수리 경로 변경만 명시적으로 reuse 허용 목록과 source freeze에 넣는다.

Jev가 재귀 분해·관계·필요 시 공개 수리 선택을 맡는다. 구현 작업자는 `claude-opus-5-5` / `medium`, 실행 슬롯2, 최대 작업자30, 구조 제한·수리 최대2회·전체14,400초 deadline은 D067과 같다. 누적 기존 v3 장부를 사용하며 입력 한도는 null이다. 장부 ID/이력·미정산 정지·잔액/모델/목적지 확인은 유지한다. GET models는 추론 없이 확인하고 기본 모델은 `jev-latest`다.

이번 사용자는 Jev 전체 조건 재실행을 요청했으므로 Claude 기준선과 나머지 조건은 D067의 보존된 기록과 비교한다. **D067은 네 조건 병렬, D068은 한 조건**이라는 실행 경합 차이를 명시한다. 표본 각1회, 배정/생성/캐시/공급자 부하 변동을 포함하므로 수정의 인과 효과나 일반적 우위를 단정하지 않는다.

## 검증과 측정

먼저 D067 공개 실패 원본을 읽는 로컬 replay로 전송 바이트 절감, case 보존, 알려진400/불확실전송 분리, 실제 blocker와 미실행 항목에 따른 후보 범위를 확인한다. 후보 파일은 수정하지 않는다. 주요 반례 focused 검사 후 필요한 회귀 검사를 실행하고 독립 리뷰를 통과한 소스를 실제 호출 전에 동결한다.

새 실행의 공개85개 검사와 동결 후보에 대한 독립63개 채점이 모두 통과해야 완료다. 숨김 검사 상세는 구현/수리 입력에 넣지 않는다. 실행 시간은 arm 시작부터 공개 검사/정리 종료까지이며 독립 채점 시간과 공유/개별 preflight를 별도 명시한다. 성공 후보끼리만 완료 속도 차이를 계산한다. 이전 실패 Jev 전체 조건과는 시도 시간·비용 및 완료 여부를 비교한다.

Jev POST와 Claude CLI 호출을 stage별로 집계하고 입력/출력/캐시 생성/읽기, 원시 receipt, 총 API 단가 환산 비용을 보존한다. 누락은 null, 확인 소계는 별도다. 월 구독 실제 배분 청구와 API 환산값은 다르다. 기존 catalog 준비비는 새 지출에 더하지 않는다. 별도 Opus5.5 monitor에는 내부 경로/식별자/소스 없는 수치 패킷만 주고 비용·시간을 별도 집계한다.

수리가 자연적으로 발생하지 않으면 실제 수리 호출 성공·작업자 절감은 미측정으로 보고한다. 새 생성 실패를 과거 숨김 근거로 고치거나 임의 성공 처리하지 않는다. 모델 입력 거절/불확실 실패의 자동 재전송은 없으며 결과·정산 근거를 먼저 보존한다.

## 기록

실행 원본은 새 `benchmark-runs/d068-*`에 둔다. root는 종료 후 총 시간/토큰/비용 산식과 비교 한계, 미실행/실패/남은 일, 후보·로그·미커밋 변경·컨테이너 잔류를 기록한다. 이 문서는 사전 계획이며 효율 개선의 실측 근거가 아니다.
