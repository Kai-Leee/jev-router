# D073 후속 — 담당 추론 입력의 의미 보존 투영

첫 실행 두 조건은 보존한다. 새 전체 개발은 공개79/93·독립60/63, D071 보존 후보는 공개67/93·독립49/63이었다. 두 조건 모두 기존 담당 추론에서 서버 HTTP400 `model_input_limit`으로 종료했고 담당 답과 실제 수리는0이었다. 로컬 v4 admission은 통과했다. 원본4439개와 실행 소스270개 변경0을 `benchmark-runs/d073-preflight/closeout-integrity.json`으로 확인한 뒤에만 후속 소스 수정을 시작한다.

## 변경과 가설

기존 `inferred-v1`/v8을 보존하고, `benchmarks/e2e-swe/manifests/d073-inferred-v2.json`의 v9에서만 `inferred-v2`를 선택한다. 질문·규칙은 `docs/orchestration/contracts/adaptive-inferred-repair.v2.json`에서 읽는다. Jev는 모든 기존 산출물 계약을 후보로 받으며 `unknown`을 선택할 수 있다. controller가 선택된 기존 artifact ID에서 실제 담당/쓰기 경로를 결정한다.

실패 원문과 해당 실패의 원문 요구사항, 전체 기존 artifact의 의미·경로·담당·의존 계약을 inline으로 유지한다. 알려진 성공 검사는 상태/식별자로 요약하고 중복 실패 설명과 선택지 설명을 줄인다. 원본과 생략 내역은 controller 증거로 보존하되 로컬 경로/hash를 모델이 읽은 의미 근거로 세지 않는다. 미도달 assertion을 관측 실패로 바꾸지 않으며, 실패/불확실 응답과 부분 답을 적용하지 않는다.

로컬 토큰 추정과 장부 상한은 계속 비차단/null이다. 공식 body/schema/서비스 제한은 유지한다. 오프라인 prototype26문항은187728→91155B였으며 wire 바이트 비교다. 실제 입력 토큰·provider 수락·수리 정확도·전체 비용 절감은 미측정이다. 질문만 나누면 공통상태가 반복되므로 후속은 전체 실패를 한 번에 질문하는 투영을 사용한다. 공식64문항 초과는 기존의 명시 중단을 유지하며 자동 다중요청은 추가하지 않는다.

## 실제 검증 순서

1. D07126실패와 D07314실패에서 v2 입력·답·실행 연결을 오프라인 검증하고 독립 검토한다. v1 요청 재현과 unknown/오류/부분답 거절도 확인한다.
2. source·manifest·공개93 mapping·현재환경·동일장부를 다시 고정하고 첫 실패 원본까지 보존 검사한다.
3. `benchmark-runs/d073-focused-old-01`과 `benchmark-runs/d073-focused-new-01`에서 D071/D073 종료 후보를 각각 읽기 전용 상속한다. 정확한 공개 실패 재현 후에만 새 v2 담당 추론→수리 선택→모델/effort 선택→기존 담당 작업자를 실행한다.
4. 공개93 전체 재검사와 root의 독립63 채점으로 수리 결과를 확인한다. 수리2회·작업슬롯2·기존환경을 유지한다. 실패·불확실 POST는 자동 재전송하지 않는다.

후속은 이미 생성된 후보 수리다. 새 분해/관계/초기 개발을 반복하지 않는다. 과거 개발시간과 후속 수리시간의 산술합은 참고치이며, 중간 분석·코드 수정·대기시간이 포함된 자동 E2E 완료시간이나 Claude 단독 대비 실측 가속률로 부르지 않는다. 첫 실패2회의 사용량 결측은null, 확인된 환불0은 별도 증거로 유지한다. 월구독 배분은 미상이다.

## 역할

[D073 역할](../agents/D073_PARALLEL.md)을 유지한다. `d067_budget`는 v2 투영/계약/검증/실행 연결, root는 manifest/공통 runner/planner/실제 호출/독립 채점, `d067_review`는 보존 수리와 source v7/v8 연결, `d071_review`는 독립 입력·권한·동결 검토, `d068_failure`는 보존 수리별 회계, `d067_skills`는 기존 기록 규칙 적용을 맡는다. 실제 호출과 장부 작업은 root만 한다.
