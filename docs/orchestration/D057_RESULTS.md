## 실패 및 기대와 다른 관측

- 분할 계획을 실제 작업자로 연결했지만, Jev가 child_count1을 골라 분할이 발생하지 않았다. 실제 typesafe/jev-1.13-20260917 응답이며 강제 resource keep이나 과거 결과 재사용이 아니다. maxdepth3/maxleaves8는 적용 가능한 상한이었고 실제깊이0이다. 단1개의80의무 묶음이 실행됐다.
- Jev의 첫 공개 검사는 JSON/YAML/literal 모두 리스트 기본값에서 실패했다. 공통 사전 정책의 공개 수정1회 후 공개 검사는 통과했다. 이 실패·수정 시간을 제외하지 않았다.
- 최종 독립 테스트의 실패는 TestDefaults::test_defaults_in_initializer다. union 기본값 기대3이 True였다. 후보 parser.py114–126의 union은 첫 변환 가능 후보를 채택하고,174–177의 bool 분기는 int를 bool(v)로 변환한다. 이 코드와 채점의 True!=3 관측이 일치한다. 숨겨진 테스트 소스/참조 구현을 작업자에게 주지 않았으며, 이 오류는 최종 평가 후 controller가 출력 영수증으로만 확인했다. 후보 수정·재채점은 하지 않았다.
- 공개 검사가 union 기본값의 잘못된 분기를 잡지 못했다. 공개 검사 통과와 전체 제품 완료는 동일하지 않다는 실제 실패다.
- 사전 전체 테스트 명령이 D056 보관 테스트를 잘못 발견하여 import 실패했다. 직접 만든 보관 방식과 광범위 node --test의 조합에서 발생한 검증 결함이다. 보관 원본을 남기고 package.json을 실제 test/*.test.mjs로 한정했다. 수정 후739/739 통과, skip0. 마지막 불확실성 guard의 관련8테스트도 이후 통과했다. fixture 테스트 성공을 이번 제품63/63과 혼동하지 않는다.
- Opus 모니터의 contract hash 차이 의문은 raw JSON 파일 해시와 재귀 key정렬 canonical hash의 차이다. 로컬 재계산이 plan.metrics.contract_sha256과 정확히 일치한다. [해시 감사](../../benchmark-runs/d057-contract-hash-audit.json). 모니터 원문은 수정하지 않았다.

## 비교 범위와 남은 일

모델/effort, 공통 원문80의무·85테스트 명세, 이미지, source24개 해시가 동일하고 실행 중 소스 변경은0이다. 두 후보 모두 새 빈 경로에서 시작했다. 다만 A첫작업자write16경로, Bleaf13경로이며 B의 ir.py/__init__.py/__main__.py는 공통16경로 통합으로 넘긴다. 따라서 단일판단기만 바꾸는 실험이 아닌 전체 workflow 비교다. A부터 순차 각1회로 모델 변동·시간대·캐시 순서 효과가 남는다. 병렬 작업자는 발생하지 않았다. 입력 테스트명세85개는 독립 executable63개와 다른 단위다.

분할이 실제 발생하는 과제/조건, 양쪽 독립완료, 반복·순서 교차가 이후 속도 개선 주장에 필요하다. 평가 정보를 반영해 제품을 고치거나 공개 체크를 확장하면 새 조건으로 기록해야 한다. 현재 실패 실험을 성공으로 덮어쓰지 않는다. 알려진 controller 마지막180초 구간의 fractional timeout 검증 문제는 이번 실행에서 발생하지 않았고 다음 revision에서 보완할 항목이다. 추가 유료 반복은 이번 결과에 포함하지 않았다.
