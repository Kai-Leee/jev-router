## 4. 남길 것

- 읽기 범위 확대(`candidate-v1`): 같은 조건 비교에서 유일하게 결과를 바꾼 요소다.
- `repair-budget-v2`, ledger_op lock 해제와 live 예약 허용, GET 재시도: 실패를 막는 안전장치이고 기존 동작을 바꾸지 않는다.
- `inferred-v3`, 정책 v8/v9 체인: 오프라인 검증까지만 했다(1348/1348).
- 순차 실행 원칙: 병렬 실행은 원장 lock 장애를 낸 적이 있다(D079).

## 5. 다시 할 것

1. 공개 통과 후 독립 실패를 고칠 경로가 없다. 02에서 62/63이 나왔다. 수리 루프는 공개 실패가 있어야만 돈다.
2. 실측이 없는 기능: 요청 분할, check_error 질문, 작업자 진단, GET 재시도. D081 계열을 순차로 다시 돌려 측정한다.
3. 실행 전 점검의 models GET은 아직 1회만 시도한다(04). 비용은 0이다.
4. artifact-repair 작업자 프롬프트에 `recovery_evidence`가 들어가지 않는 것으로 보인다(미확인).
