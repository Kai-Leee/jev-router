## 핵심 설계 제안

작업 분해 트리, 검증된 산출물을 잇는 DAG, 파일·자원 충돌을 별도 관계로 관리한다.
Jev는 의미적 분할·관계·담당·프로필·실패 후 행동을 선택하고, 코드는 제약·순환·임계 경로·슬롯을 계산한다.
새 작업 설명 생성은 준비 역할에 남기고 반복되는 질문은 문서에서 읽어 붙인다.
Jev 선택값을 등록 handler로 연결하고 메인의 동일 판단 반복을 기본 단계로 만들지 않는다.
후속 해제는 작업자 종료가 아니라 필요한 산출물 버전의 검증 성공에 연결한다.

최대 작업자 수를 늘리는 것과 실행 가능한 병렬성이 늘어나는 것은 다르다.
D062 결과 문서의 개별 포함/제외 판단을 합친 용량 위반은 후보 단계의 용량 보장과 예약 갱신으로 다룬다.
공개 검사 실행 mapping, 지역/통합 검사 준비 조건, artifact 경계를 먼저 준비한다.
실제 비교는 같은 DAG 실행기·작업자 조건에서 Claude/규칙/Jev 판단을 비교해 구조 개선과 판단기 효과를 구분한다.

## 메인이 이어받을 때

1. 최신 STATE·사용자 요구와 이 설계의 제안 사항을 대조한다. 예산·동시성·유료 실행 허용 범위를 과거 기록에서 자동 확장하지 않는다.
2. 실행 검사 mapping과 artifact/task 계약을 첫 구현 묶음으로 정한다.
3. 역할별 소유 파일·입출력 계약을 정한 뒤 어댑터/그래프/검증/UI를 나누어 진행할 수 있다.
4. 계약 fixture와 오프라인 반례 검증을 먼저 갖춘다. 이 문서 자체는 runtime 검증이나 성능 결과가 아니다.
5. 채택 시 공용 인덱스·AGENTS·CLAUDE 진입점에 링크하고 메인 결정 번호를 부여한다. 사이드에서는 번호를 선점하지 않았다.
