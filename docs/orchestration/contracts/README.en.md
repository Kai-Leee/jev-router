# Canonical locations read by the runner — D028

> English translation of [README.md](README.md). The Korean original is authoritative if they differ.

The repository-relative path is `docs/orchestration/contracts/`. The current absolute path is `/Users/lee/workspace/plugins/jev-router/docs/orchestration/contracts/`. The code resolves paths relative to import.meta.url, so it reads the same canonical files even when the terminal working folder differs.

- `questions.v1.json`: the original English questions for each judgment kind, their type, and the answer options and their meanings. At run time, sentences are not newly generated or summarized. Only the requirementId slot is substituted. Dynamic options for task/worker/failure are attached as is from the corresponding task/profile/error documents, and unknown is kept.
- `profiles.v1.json`: model + effort + adapter + enabled flag + verification level. There are 2 enabled mock profiles. 1 past D025 Opus5.5 medium profile is disabled. Current availability verification of real profiles and the live adapter are not connected.
- `worker-task.v1.json`: the fixed instructions and return fields given to the worker. The program attaches the task card, the original goal text, and related requirements and evidence. It does not present a new work plan as generated by an LLM.

The read/build code is loadDocumentContracts → prepareDocumentRequest → createWorkerTask in `src/orchestration/document-contracts.mjs`. The existing D027 frozen comparison code/experiment CLI stays as is. Whether the new path is used is checked in request.state.contractSources by absolute path/version/JSON content hash. The hash differs from a raw file hash. It is a hash of the JSON content.

```sh
node bin/check-document-link.mjs benchmark-runs/d028-document-link-NEW.json
node --test test/document-contracts.test.mjs test/document-router.test.mjs
```

Connection: load documents → attach the registered worker question → mock sim_high response → spawn_worker → creation arguments that contain the document's fixture-model/high + ui task/evidence/return contract. This check does not create a real process or model. Real Claude API/CLI calls and automatic goal→work plan generation are a separate connection step. If a live adapter is passed by mistake, the current factory rejects it.

2026-10-09 verification: 22/22 test pass. Actual mock connection log: benchmark-runs/d028-document-link.json. It confirmed that document questions are attached as is, that document changes are reflected, that model/effort is kept, and that disabled profiles/unknown enums/live adapters are blocked. The full regression was not repeated for this independent module change. The D027 361/361 record is not claimed as a current rerun result.

Arbitrary changes to the existing question type/answer enum are rejected, because they conflict with the run handler contract. To add a new answer type, update the document and the handler contract together, and test them. Edit the natural-language content of questions in the document. Results do not guarantee automatic correct answers or run permission.
