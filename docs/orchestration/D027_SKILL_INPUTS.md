# D027 — 향후 스킬 생성에 필요한 정본 자료

현재는 새 운영 스킬을 배포하지 않는다. 사용자 요청의 '무엇을 왜 어떻게'를 다음 정본에서 가져오도록 준비한다. 이 문서는 기존 jev-decision-records를 대체하지 않는다.

1. 목적: 반복 라우팅 판단을 Claude에서 이전하고, 분할·병렬화로 전체 품질을 유지하면서 wall time을 줄이는지 검증. 시간 개선은 아직 미측정.
2. 트리거: 목표 신규 등록, leaf/분할 선택 필요, worker 생성, 오류 발생, 요구사항 근거 변경. 매 토큰/명령마다 재질문하지 않음.
3. 문서 입력: D027_CONTRACT의 Goal/requirements, Task card, Split sketch, Worker profiles, Failure catalog, Question pack, Evidence records. JSON 정본과 버전/해시 보존.
4. 사전 준비: 초기 Claude 생성→정적 검증→원문 연결 검토→질문/옵션/handler 고정. 반복 시 직접 문서 읽기/자료 구성하며 신규 계획 생성과 반복 선택 비용을 분리.
5. 타입과 실행: choice/noul→등록 handler. 알 수 없는 enum/확률 오류/오래된 상태/계약 변경 거절. finish 없음. 모델+effort는 하나의 프로필 ID.
6. 분할: 충분한 문서+유효한 splitSketch+명시 임계값. 임계값 후보를 비교하며 운영 기본값은 null. 실제 새 자식 구조가 승인 sketch와 달라지면 새 판단 필요.
7. 병렬: 트리 구조와 의존성 구분. 부모 범위 안 쓰기, 공유 파일 직렬화, 선행 실패 전파, 자식 결과 후 통합/검증. 운영의 격리 workspace·비파일 공용 자원 검증은 미구현.
8. 예외: 근거 부족 수집, 새로운 오류 범주 확장, 가용 프로필 없음, 입력 초과, 불확실 API 결과 정지. 자동 재시도로 비용/중복 실행 숨기지 않음.
9. 출력 기록: event/request/response/policy/handler/worker/observation 참조. synthetic/live/estimated를 구분. 기존 장부 그대로 사용.
10. 검증: 문서 정적 검사→모의 라우팅 및 실패 반례→실제 고정질문 라벨 평가→동일 목표 E2E 비교. 문법 검사를 실제 품질로 올리지 않음.
11. 인계: 사용자의 확정 지시, 최신 goal/spec/plan/질문 revision, 수행 중 ID/불확실 호출, 파일 소유권, 원본 로그, 남은 판단/다음 트리거. 압축 요약만을 정본으로 삼지 않음.
12. 채택 기준: 독립 품질 저하 없이 전체 시간·비용이 개선되는 조건을 측정 후 기록. 그 전에는 새로운 skill에 개선 보장 문구를 넣지 않음.

구현 전용 지침과 사용자 제품 UI 설명을 구분한다. 문서를 재사용한 실제 행동 증거가 확보된 뒤 SKILL.md 생성 및 호스트 선택/로드 검증을 따로 수행한다. 현재 자동 스킬 선택·운영 워커 생성은 미검증이다.
