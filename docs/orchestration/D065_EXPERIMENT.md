# D065 — 실제 DAG 연결 단일 조건

2026-10-11 (Asia/Seoul). 상태: 실행 전 프로토콜. [구현](D065_IMPLEMENTATION.md), [역할 계약](../agents/D065_PARALLEL.md), [runner](../agents/D065_RUNNER.md). 이 문서가 실제 호출이나 제품 완료의 증거는 아니다. 실제 원본은 새 `benchmark-runs/d065-live-01/`에 기록하며, 이미 사용된 경로를 덮어쓰거나 재개하지 않는다.

## 고정 조건과 시작 기준

- 과제: 원문 해시가 고정된 E2E-SWE `openapi_python_client`. D056의80개 요구사항·85개 공개 검사 설명·16개 파일 경계를 사용한다. 과거 후보 소스를 복사하지 않는다.
- 판단: Jev `jev-latest`, 직접 목적지 `https://jev-ai.pro/api/v1/systemone`. 공개 원문을 포함한 상태로 작업자 수2..16과 실제 파일별 소유권을 선택한다. 모델 선택/노력도는 이번 조건에서 고정하며 추가 판단 호출에 넣지 않는다.
- 작업: Desktop 관리 Claude CLI의 `claude-opus-5-5`, medium, 최대 동시2. 각 파일 작업은 새 CLI 세션이다. worker ID는 스케줄 자원이며 세션 기억 재사용을 뜻하지 않는다. 선택한 담당자 수와 관계없이 정상 끝까지 진행하면 구현 CLI16회를 예정한다. 담당자 수 자체를 호출 수 절감으로 계산하지 않는다.
- 계획: 실제 owner 선택을 반영한16개 구현 노드와1개 공개 검증 노드. 의미 handler의 분할 commit은 이 선택 결과를 적용하는 로컬 동작이다. 별도 Jev 분할 질문 성공으로 세지 않는다. 명시된 의존 관계는 코드로 연결한다.
- 실행 환경: 고정 Docker 이미지 ID와 linux/amd64, network none, 읽기 전용 root와 source mount, 실행 가능한 `/tmp:rw,exec,size=2g`. 원본 Personal OS/Vault와 이전 실험 결과는 수정하지 않는다.
- 시작 조건: 독립 검토의 확인된 차단 결함 없음, 전체 Node 회귀 통과,7개 정상 suite/81개 결함 대조의 고정 증거와 현재 소스 일치, 실제 정상85개 Docker 재검사·CLI OAuth·Python/의존성·Jev models GET 사전 검사 통과.

사전 검사 또는 코드 검증의 실패는 유료 모델 실패로 집계하지 않는다. 새 유료 실행은 root만 한 번 시작한다. Jev 누적 장부는 기존 ID와 사용량을 유지한다. 시작 직전 잔액·pending 상태를 다시 읽는다.

## 한도와 중단

전체 시도 deadline14,400초를 명시한다. 개별 작업자10분 제한은 없다. Jev 계획은 최대32회·입력1.5M·요청240,000바이트이며 누적10M 장부와65,536 입력 토큰 예약 정책도 함께 적용한다. 이는 목표 호출 수가 아니라 보호 한도다. 후보 하나는 로컬 처리한다.

자동 재시도0, 공개 실패 후 자동 수리0, 숨김 피드백을 이용한 수정0, 모델 fallback0이다. 알려진 실패면 후속 의존 작업을 해제하지 않는다. 외부 응답·프로세스·컨테이너 정리 또는 journal이 불확실하면 그 상태를 보존하고 재전송하지 않는다. 소스가 실행 중 바뀌면 결과에 표시한다.

## 기록할 측정

- 전체 시도 wall: 실행기 시작부터 사전 검사·계획·구현·공개 검증·정리·terminal 결과까지. 독립 채점과 별도 모니터는 별도 구간이다.
- 계획 wall과 Jev HTTP 호출 wall은 구분한다. 정확한 질문·응답·선택 source·배정·semantic commit·실제 plan을 연결한다.
- Claude 호출 wall의 합은 동시 실행 시 경과시간과 다르다. 개별 호출/입력/출력/캐시 생성/캐시 읽기/최종 receipt/API 환산을 보존한다.
- 공개 검사: 실제 실행 ID·버전·환경·명령·assertion·skip·종료값·revision 벡터. 단순 구문 준비 검사16개와 최종 의미 검사85개를 섞지 않는다.
- 제품 결과: 별도 원본 grader에서63개 전부 실행·통과한 경우에만 독립 완료로 인정한다. 실패·일부 출력은 시도시간이고 완료시간은 `null`이다. 공개 검사와 독립 채점이 서로 다르면 둘 다 남긴다.
- 비용: Jev 입력 토큰의 [공식15M/$9 토큰팩 환산](https://jev-ai.pro/pricing)($0.60/M), Claude 최종 CLI receipt의 API 환산을 사용한다. 두 값 모두 월 구독의 실제 청구 배분과 다르며 실제 청구액은 `null`이다. 비용 결측은0으로 채우지 않는다. 별도 Opus 모니터 호출은 구현 비용과 분리한다.
- 환경 검사/컨테이너 생성·정리 및 입력 materialization/검증 overhead는 전체 wall에 포함된다. 준비된 같은 불변 이미지의 의존성 조회를 모든 파일 경계마다 반복하지 않는다.

이번에는 조건이 하나이므로 Claude 단독 대비 개선율, 일반화된 속도 우위, 재귀 분해·관계 판단 정확도 또는 최적 작업자 수를 주장하지 않는다. 이전 실패와 이번 시도의 시간만으로 우열을 계산하지 않는다.

## 실행 명령

저장소 루트에서 root가 gate 통과 후 실행한다:

```sh
npm test > benchmark-runs/d065-local/regression.log 2>&1
node scripts/audit-dag-public-checks.mjs --verify-frozen
node scripts/dag-e2e.mjs benchmark-runs/d065-live-01 --spend
```

마지막 명령은 유료 호출을 포함한다. `--spend` 실행 내부에서 실제 사전 검사를 수행하므로 같은 정상 검사를 root가 직전에 다시 중복 실행할 필요는 없다. 전체 결함 대조 원본은 공개 검사 담당이 이미 실행·동결한 결과로 확인한다. 단일 terminal 결과 뒤에는 별도 원본 채점과 Opus 모니터를 수행하며 새 유료 구현 반복은 자동 시작하지 않는다.
