# D057 — 실제 개발 완료 시간 비교

2026-10-10. 사용자 요청: “실제 개발 완료까지 얼마나 빨라지는가를 측정해보자.”

## 비교 조건

A는 Claude Opus 5.5 medium이 전체 공개 OpenAPI 명세를 받아 빈 작업공간에 구현한다. B는 Jev가 동일 출처의 80개 의무·85개 테스트 명세로 재귀 계획을 새로 만들고, 같은 Claude 모델이 leaf를 구현한다. 양쪽 모두 전체 제품 통합 검토 1회와 같은 공개 검증·최대 3회 복구 기회를 갖는다. 마지막 독립 채점 결과는 작업자에게 돌려보내지 않는다.

이는 Claude 단일 구현 흐름과 Jev 재귀 위임 흐름의 비교다. 판단 모델 하나만 바꾼 인과 실험이 아니다. 각 조건 1회로 시작하며 순차 실행해 조건 사이 자원 경합을 피한다. 순서·캐시·공급자 변동은 남는 한계다. 원래 Personal OS/Vault는 변경하지 않는다.

공통 입력은 원래 공개 명세, 설치 계약, 기존 16개 파일의 인터페이스 참조와 테스트 명세다. 과거 생성 코드·정답·숨은 테스트·실패 테스트 내용은 전달하지 않는다. 파일 구조가 미리 주어진 scaffold 비교이며 목표만 주는 완전 자유 설계 비교는 아니다. 사전 문서·하네스 개발 비용은 별도 미계측으로 남긴다.

## D056에서 변경한 부분

- 반복 분할이 목적이 되지 않도록 `1=유지` 질문을 바꾼다. 의존 관계 미확정만으로 분할을 요구하지 않고 전체 완성 시간과 통합 부담을 고려한다.
- 명시 의존 간선이 없는 입력의 배정 질문을 최대 8개 묶는다. 기준점 선택은 순차다. 한 응답의 전체 유효성을 확인한 뒤만 배정을 반영한다. 원문과 예상값은 전송 후 완전 복원 검사한다.
- 실행 자원은 깊이 3, 최대 leaf 8, 동시 작업자 2다. 자원 때문에 더 나눌 수 없으면 코드의 강제 유지라고 기록하며 모델의 적정성 판단으로 표시하지 않는다. 최적값이라는 주장은 하지 않는다.
- 전역 입력 10M 장부를 유지하고 계획에는 최대 3M을 배정한다. 과거 240회 호출 한도는 적용하지 않는다. 비정상 루프용 매우 큰 100,000회 가드 외에 실질적인 호출 횟수 제한은 없다.
- 원래 계획은 여전히 명세이며 실행 상태를 덮어쓰지 않는다. 새 실행 envelope에서 leaf의 쓰기 범위와 공유 파일 순서를 적용한다. 완료된 선행 파일에 읽기 잠금을 유지해 읽는 동안 다른 작업자가 덮어쓰지 못하게 한다. 수정 범위는 보수적인 관련 파일 목록이며 의미상 독립성의 증거가 아니다.
- leaf 범위에서 빠진 `ir.py`, `__init__.py`, `__main__.py` 및 공유 인터페이스는 전체 통합 작업자가 책임진다. 최종 전체 검증을 생략하지 않는다.

## 완료와 시간

각 arm의 첫 실행 직전부터 독립 평가 프로세스가 끝날 때까지 단조 시계로 측정한다. Jev 계획, Claude 내부 계획·구현, 병렬 작업 대기, 통합, 공개 검사·복구, 최종 독립 평가를 포함한다. 실행기 개발과 공통 입력 준비는 포함하지 않는다. 단계 시간을 합산해서 병렬 실행 시간을 과장하지 않는다.

성공은 고정 OpenAPI 평가기의 `resolved=true`, reward 1, 정확히 63/63 통과, 원본 task/commit/image 일치, 후보 파일 보존, 평가 컨테이너 제거 증거로 확인한다. 프로세스 exit 0이나 공개 smoke만으로 완료라고 하지 않는다. 실패하면 `completion_wall_ms:null`이며 소요 시간은 실패한 시도의 시간이다. 양쪽 모두 완료된 경우에만 `(A 완료 시간 - B 완료 시간) / A 완료 시간`을 계산한다.

기존 긴 실행 정책의 4시간 가드를 사용한다. 작업자 호출에는 남은 시간을 적용하고 공개 smoke는 남은 시간과 180초 중 작은 값을 사용한다. 진행 중 외부 호출의 종료·정산 시간은 실제 전체 시간에 포함한다. 10분 호출 제한을 다시 도입하지 않는다.

## 비용·관측

Claude 입력·출력·캐시 생성·캐시 읽기와 CLI 보고 API 환산, Jev 입력·출력과 토큰팩 환산을 분리한다. 실제 월정액 청구액과 개발 준비 비용은 미확인이다. 요청·응답·모델 ID·소스·입력·후보 해시는 비공개 실행 폴더에 보존한다. 결과 불확실 호출을 자동 재전송하거나 장부를 초기화하지 않는다. 별도 Opus 5.5 medium 비교 모니터는 종료 후 양쪽 결과를 읽고 비용을 별도 보고한다.

## 실행과 검증

```sh
node scripts/recursive-e2e-comparison.mjs
npm test
node scripts/recursive-e2e-comparison.mjs claude benchmark-runs/d057-claude-01 --spend
node scripts/recursive-e2e-comparison.mjs jev benchmark-runs/d057-jev-01 --spend
```

`--spend`가 없는 첫 명령은 입력 검사만 한다. 각 실제 실행 디렉터리는 새 이름이어야 한다. 원본 기록을 덮어쓰지 않는다. 구현 소스와 고정 조건은 두 실행 사이에 수정하지 않는다. 수정이 필요하면 비교 불일치를 기록하고 같은 비교처럼 합치지 않는다.
