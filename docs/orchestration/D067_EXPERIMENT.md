# D067 — 상한 해제 후 4조건 병렬 비교

2026-10-11 KST. 사용자는 조건별 상한과 장부 토큰을 현재 제한 없이 사용하고 바로 병렬 진행하라고 명시했다. 이 새 승인이 D066의 조건당 700,000·누적 10,000,000 입력 토큰 정책을 대체한다. D066은 종료된 원본이며 재개하거나 수정하지 않는다. [역할](../agents/D067_PARALLEL.md), [결정](../decisions/D067.md), [이전 결과](D066_RESULTS.md).

## 비교 대상과 고정 조건

기존 E2E-SWE `openapi_python_client`의 같은 공개 원문·80개 요구사항과 D066에서 준비한 21개 구현 단위·22개 산출물·38개 파일 후보를 사용한다. `claude_all`, `jev_split`, `jev_split_relations`, `jev_all`을 새 폴더에서 한 번씩 동시에 시작한다. Claude 기준선도 다시 실행하여 같은 기간의 공급자 부하를 공유한다. D066 순차 실행은 역사적 참고로 따로 둔다.

각 조건은 재귀 분해, 최종 잎의 의존 관계, 공개 실패 수리 선택을 실제 실행기에 연결한다. 모든 조건의 구현 작업자는 `claude-opus-5-5`, effort `medium`이며 조건당 실행 슬롯 2개, 논리 작업자 최대 30명이다. 후보·영어 질문·선택지·작업자 지시·공개 검사·고정 Docker 이미지·수리 기회는 D066과 동일하게 유지한다. 상한 해제와 조건 병렬화 외에 배정 질문이나 첫 묶음 집중을 임의로 고치지 않는다. 같은 선택 문법의 Claude 판단기 비교이며 일반 Claude Code 사용 전체에 대한 우월성 실험은 아니다.

## 한도 이관

새 manifest `adaptive-dag-comparison/v2`는 `limits.planning_input_tokens:null`, `cohort_concurrency:4`를 명시한다. 누적 장부 정책은 `jev-token-budget/v3`, `max_input_tokens:null`이며 현재 장부를 명시적으로 v2→v3 이관한다. 예산 ID·누적 사용량·정산 수·마지막 정산을 보존하고 전후 사본으로 대조한다. 새 빈 장부를 만들지 않는다.

이 계약의 한도 `null`은 무제한이다. 토큰 사용량·비용의 `null`은 여전히 미확인이다. 계정 잔액, 동결/부채, 실제 모델, 정확한 목적지, 토큰 과금 모드, 요청당 65,536 예약, 불확실 정산 정지, 장부 잠금·원자적 정산은 유지한다. 무제한 정책은 실제 계정 잔액을 무제한으로 만들지 않는다.

기존 구조 제한도 유지한다: 후보 최대 30단위·60산출물·60파일, 30잎·깊이3·59노드·435관계쌍, 판단 callback 최대128, 관계 질문 배치32, 요청240,000바이트, 공개 수리 최대2라운드, 전체 조건 deadline14,400초. 개별 작업자 10분 제한은 없다. 자동 POST 재시도·불확실 호출 재전송·모델 fallback·숨김 피드백 수리는 0이다. 토큰 상한과 구조/서비스 제한은 별도다.

## 병렬 실행과 준비물 재사용

추론 전 공유 preflight를 한 번 검증하고 네 조건을 독립 경로·세션으로 시작한다. 각 조건이 끝날 때까지 수집한다. 공유 장부는 한 요청의 예약부터 정산까지 독점한다. 다른 조건의 정상 사용 중 잠금은 대기하며, 불확실하거나 정산되지 않은 예약을 성공으로 간주하거나 지우지 않는다. 따라서 네 작업 흐름의 병렬성과 Jev POST의 장부별 직렬 처리를 구분한다. 장부 대기, 실제 조건/작업자 중첩, 순수 POST·CLI·조건 wall을 각각 기록한다.

D066 catalog의 원본·준비 결과·생성 요청·source snapshot은 그대로 보존한다. 재사용 전에 원본 해시, 동일 공개 원문과 요구사항, 현재 재생성되는 prompt/schema, 생성에 영향을 주는 소스가 같음을 검사한다. budget/runner/CLI의 이번 허용 변경만 명시하고 일반적인 source 불일치를 무시하지 않는다. 검증이 실패하면 조용히 새 후보로 바꾸지 않고 실패 근거를 남긴다.

재사용이 확인되면 D067 신규 준비 호출과 신규 준비 지출은 0이다. **주 비교는 공유 preflight가 끝난 뒤 이번 각 조건의 시작/종료 장부 관측·판단·구현·수리·공개 검사·정리 wall과 실제 신규 API 환산 비용**이다. 공통 preflight 시간은 별도 필드와 cohort 경과시간에 포함하고 각 arm 시간에 반복해서 더하지 않는다. 과거 준비 시간·비용을 전액 귀속한 수치는 별도 참고 열이다. cohort 실제 신규 총지출에 과거 준비 비용을 다시 더하지 않는다. 병렬 cohort의 경과시간은 각 조건 시간의 합과 다르다.

## 성공·평가·가격

공개 7개 suite/85개 case의 실제 결과와 독립 grader 63개의 실행·skip 여부를 모두 확인한다. 완료한 후보에 한 번의 독립 채점을 수행하며 숨김 실패의 세부 내용은 구현자에게 전달하지 않는다. 성공 완료시간 감소율은 두 조건 모두 제품 완료를 확인한 경우에만 계산한다. 실패 조건은 실패까지의 시도시간·호출·비용·마지막 단계로 보고한다. arm 이름만으로 관계·수리 단계가 실행됐다고 하지 않는다.

조건별 판단/구현/수리 호출, 입력·출력·캐시 생성·읽기, 원시 영수증, 선택→실행, DAG/실제 critical path, 공개·독립 품질을 기록한다. 한 번씩의 탐색 실험이다. 모델 선택 자체의 변화, 공급자 부하·CPU·캐시·장부 경합을 잠재 원인으로 구분하며 유의성이나 고정 속도 우위를 주장하지 않는다.

단가는 D066에서 2026-10-11 확인한 [Jev 가격](https://jev-ai.pro/pricing), [Jev 문서](https://jev-ai.pro/docs), [Claude 공식 가격](https://platform.claude.com/docs/en/about-claude/pricing) 자료를 사용한다. 비교용 Jev 입력 $0.60/M·출력 무료, Opus5.5 입력 $4/M·출력 $20/M·5분 캐시 생성 $5/M·1시간 $8/M·읽기 $0.20/M이다. 실제 월 구독 청구 배분은 미확인이다. 독립 채점 시간과 별도 Opus5.5 medium 모니터 비용/시간은 분리한다. 모니터에는 내부 경로·식별자·원문을 뺀 수치 패킷만 전달하며 이는 원시 근거 감사가 아니다.
