## Initial contracts and review gates

- Assertion mapping: narrowing requires the controller-pinned assertion contract and exact checker/runtime/plan/environment/artifact-revision binding. Missing, duplicated, out-of-order, unknown or stale assertion evidence must not assign a precise fault owner. `not_reached` stays separate from an observed failure. A mapped failure mixed with an unmapped failure keeps the affected task's complete outputs in the conservative fallback.
- Artifact repair: candidate `artifact_ids` must belong to its selected `task_ids`, and every selected task must own at least one selected artifact. Narrowing the worker view must not mutate the original DAG or drop outputs. Inherited files retain exact bytes and executable mode, unauthorized writes fail, unselected workers receive no model call, and fresh local/full-public checks still run.
- Token admission: official exact tokenizer/counter absence is an explicit limitation. A byte-derived heuristic is neither exact model tokens nor a proven upper bound. Full-request billed input observations do not prove state-plus-longest-question context size. The admission record must bind the exact request/model/policy version sent next; a local refusal is separate from a provider failure or unknown usage.
- Cross-role integration: preserved requirements and assertion meanings, public contract hashes in fresh source pins, no stale request after admission, no missing artifact manifests, explicit outcome/billing uncertainty, and unchanged legacy opt-in behavior.
