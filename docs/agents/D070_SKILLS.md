# D070 — 균형 분해와 별도 실제 수리의 스킬 기록 검토

2026-10-11 KST. [D070 역할 계약](D070_PARALLEL.md)과 [실험 계획](../orchestration/D070_EXPERIMENT.md)을 읽고 기존 단일 `skills` 담당을 이어 맡는다. [D069 적용 기록](D069_SKILLS.md)과 과거 실패·성공 원본은 보존한다. 아래 사전 검토에 이어 실제 결과를 적용했다. **A는 고정 148개 검사에서 시간·환산비용이 모두 개선됐으나, 후속 공개 설명 진단 0/8로 더 넓은 동일 품질 우위에는 미달했다.** B의 별도 실제 수리 성공과 분리한다.

## 목적과 소유권

현재 사용자 목표는 공개 85/85·독립 63/63·생략 0을 유지하면서 성공한 과거 Claude 단독 조건보다 **완료 시간과 공식 단가 환산 비용을 모두 낮추는 것**이다. 큰 n9 잎의 집중 원인을 분석하고 유용한 균형 분해를 고안한다. 별도 실험은 보존 D068 실패 후보의 새 사본에서 실제 Jev 수리 선택과 선택된 Claude 작업자 실행을 검증한다.

[jev-skill-maintenance](../../skills/jev-skill-maintenance/SKILL.md)와 [jev-decision-records](../../skills/jev-decision-records/SKILL.md)를 계속 사용한다. 이 역할은 D070_SKILLS와 MAINTENANCE의 기록을 소유한다. 스킬 본체·reference·helper·schema·설치 사본은 현재 수정할 필요가 없다. root가 실제 공급자·Docker·장부·채점·모니터와 결과 정본을 소유하며 이 기록을 이유로 새로운 실행을 시작하지 않는다.

## 기존 규칙의 재사용 판단

| 동시 실행의 경합 | shared preparation/concurrency, ledger wait·observed overlap, timing boundary | A/B의 별도 시간·토큰·비용과 실제 겹친 구간을 보존한다. 동시에 시작하라고 요청했다는 사실만으로 실행 중첩을 확정하지 않는다. 직렬 장부 처리·공급자 대기·작업자 경합을 같은 시간으로 합치지 않는다. |

기존 [record-contract](../../skills/jev-decision-records/references/record-contract.md#artifact-dag-evidence)와 SKILL 본체로 위 사항을 다룰 수 있다. 현재 필요한 것은 실험별 증거 연결이며 새 재사용 규칙이나 스킬은 아니다. 원인/배정 API·분해 정책·계시 경계·판정 코드는 각 담당 문서와 root의 실행 전 프로토콜이 정본이다.

## 먼저 제안하는 최소 기록 보완

1. **선택 과정을 설명할 때** controller의 허용/제외 후보와 근거, 실제 Jev 선택, 그 뒤 적용된 계획을 나누어 기록한다. 분할 결과만으로 Jev가 더 작은 묶음을 자율 선택했다고 쓰지 않는다. 정확한 필드/API를 스킬에서 새로 정하지 않는다.
2. **결과 표에는** A 새 개발과 B 보존 후보 수리를 별도 행/분모로 두고, B의 시작점·재검사·수리·채점과 기존 준비의 재사용을 명시한다. 병렬 수행의 합산 작업시간을 사용자 대기시간으로 바꾸지 않는다.
3. **목표 판정은** 제품 완료, 완료시간 비교, 공식 환산비용 비교를 각각 표시한다. 시간과 비용을 임의 가중 종합점수로 바꾸거나 한쪽 개선만으로 전체 목표를 달성했다고 하지 않는다. 조건당 1회·과거 cohort 경합 차이의 한계를 유지한다.

이는 현재 승인된 실험에 기존 규칙을 적용하는 제안이며 새로운 runtime 정책을 확정한 것이 아니다. 구현과 실제 근거에서 반복 가능한 누락이 확인될 때만 기존 reference의 최소 보완을 다시 제안한다. 지금은 reference를 변경하지 않는다.

## 검사·인계

변경 없는 스킬의 구조 검사·helper 테스트·프로젝트 회귀는 반복하지 않는다. 기존 read-only inventory로 원본/설치 사본 상태만 확인하고, 새 역할 문서와 MAINTENANCE에 공백 오류가 없는지 diff로 확인한다. 이 검사는 스킬 발견/호스트 호출·분해 품질·실제 수리·사용자 효율을 입증하지 않는다.

다음 trigger는 root가 확정한 구현/실험 경계나 실제 측정 근거 전달이다. 수치와 결과는 root의 통보 후 이 문서에 이어 반영한다. 실제 유료 호출·Docker·장부·설치·과거 문서/실험 원본 변경·커밋/푸시는 이 역할에서 하지 않는다.

사전 검증의 실제 inventory는 exit 0이며 records tree `157d7f3f2aec6d3b7179a2c2db797bb0ff2dfbdbf32e65cbd22e1a025a90b371`·reference `5222b8c8a9923d0d97ef4dce8737bb00be070b6c14f240fdfe5895122c1dde9d`가 D069 종료 관측과 같다. 원본 스킬 2개, maintenance tree `7445e650…`, Codex records 사본 `93710658…`, 기존 cache·검사기·설치 부재 상태도 유지됐다. Codex records 사본은 원본과 `SKILL.md`·reference가 다르며 갱신하지 않았다. host discovery/invocation verified는 false다. 미추적 소유 문서 2개를 각각 `git diff --no-index --check /dev/null <문서>`로 확인해 신규 내용 차이에 따른 exit 1, 공백 오류 출력 없음이었다. 사전 문서 쓰기를 종료한다.

## 2026-10-11 후속 — 고정 검사 효율과 공개 품질 회귀의 분리

[분석 01](../../benchmark-runs/d070-analysis-01/analysis.json)의 A는 공개 85/85·독립 63/63·생략 0을 통과했다. arm 본체는 2,064,734.652875ms(34분 24.735초), cache 포함 4,267,230토큰, 공식 단가 환산 USD12.1814126이다. 성공한 과거 D067 Claude 단독의 같은 arm 경계 대비 시간은 5.317960%·환산비용은 42.364260% 감소했다. 독립 채점 17,799.471083ms, B 수리, 추가 진단, 준비·모니터는 이 arm 수치와 별도이며 실제 청구·월 구독 배분을 뜻하지 않는다. 각 조건 1회·과거 동시성 차이·A/B 실제 경합을 유지하므로 분해 정책의 인과 효과나 반복 가능한 속도 우위로 일반화하지 않는다.

[추가 공개 진단](../../benchmark-runs/d070-public-description-probe-01/report.json)과 [동일 진단 비교](../../benchmark-runs/d070-description-comparison-01/result.json)는 요청 본문 설명과 모델 설명이 다른 경우, 본문 설명만 있는 경우를 각각 네 함수에서 확인했다. A는 0/8, 과거 Claude 단독과 D069는 각각 8/8이다. 진단은 모델 호출 0·숨김 검사 읽기 0이며 원래 공개 85+독립 63 gate를 소급 변경하지 않는다. A에서는 모델 설명이 본문 설명을 대신하거나 본문 설명이 비어 있었다. 따라서 고정 gate의 효율 개선은 관측 사실이지만 **추가 공개 명세까지 같은 품질을 유지한 전체 효율 우위는 달성하지 못했다.** [진단 감사](../../benchmark-runs/d070-review/description-probe-review-01.json)의 같은 입력·probe와 후보 원본 보존 근거를 함께 따른다.

[A 수리 감사](../../benchmark-runs/d070-review/development-repair-review-01.json)에 따르면 두 수리 라운드에서 Jev가 받은 선택지는 A19/n14 수리 또는 중단뿐이었다. IR·operation builder·generator 담당은 후보와 작업자의 읽기/쓰기 범위에 없었다. 실제 Jev 선택을 앞단 원인까지 검토한 선택으로 확대하지 않는다. 정적 감사에서는 `BodyIR.description` 전달이 빠진 앞단이 보존됐고, 수리는 template의 별칭 탐색과 모델 설명 대체를 추가했다. 원래 fixture는 본문/모델 설명이 같아 이 차이를 검증하지 못했다. 예상 문구 하드코딩으로 판정한 것은 아니며, 실행 중 어떤 renderer 분기가 사용됐는지는 계측되지 않았다.

별도 [B 수리 결과](../orchestration/D070_PRESERVED_REPAIR_RESULTS.md)는 보존 실패의 새 사본에서 Jev 선택 1회·Claude 수리 1회 후 두 gate를 통과한 실제 성공이다. B runner 533,346.788666ms·새 호출 2개·125,964토큰·환산 USD0.2762162는 이전 후보 개발비를 제외한 수리 분모다. A의 공개 설명 회귀를 B의 성공으로 상쇄하거나 carry-forward 9명을 대조 실험으로 입증한 9회 절감으로 바꾸지 않는다. 동일 U15/U16/U17의 3→1 worker·환산비용 6.919988% 증가 관측도 전체 A 평균에 숨기지 않는다.

남은 개선 제안은 본문 설명의 producer→consumer 전달 증거 확인, 실제 앞단 후보와 작업자 읽기/쓰기 범위를 연결하는 방식 검토, 두 설명 경계를 공개 회귀 검사로 다루는 것이다. 이는 다음 변경·측정에서 확인할 내용이며 구현 완료나 새 실행 결과가 아니다. 기존 기록 규칙이 검증 범위·후보 제약·실제 실행·반증 보존을 이미 다루므로 새 스킬이나 reference를 추가하지 않는다. 별도 [Opus 수치 모니터](../../benchmark-runs/d070-monitor-01/result.json)는 `claude-opus-5-5` identity 확인 후 attention으로 검토를 마쳤다: 37,244.205833ms·17,278토큰·공식 환산 USD0.182832. 도구 없는 숫자 패킷의 관찰 검토이며 생략된 phase/local counts는 모니터에 미상으로 남는다. root의 별도 phase-analysis·planning-review 감사와 같은 검증 수준으로 합치지 않는다. 이 역할의 후속 쓰기는 소유 문서 2개에 한정한다.

후속 검증은 소유 문서 2개 각각의 `git diff --no-index --check /dev/null <문서>`에서 신규 내용 차이에 따른 exit 1·공백 오류 출력 없음이다. reference SHA-256 `5222b8c8a9923d0d97ef4dce8737bb00be070b6c14f240fdfe5895122c1dde9d`도 사전 관측과 같다. 변경 없는 스킬 구조/helper/프로젝트 검사를 반복하지 않았고 설치 사본을 갱신하지 않았다. 문서 쓰기를 종료하며 모니터 결과나 새 구현·실측 근거가 있을 때만 필요한 상태를 이어 갱신한다.
