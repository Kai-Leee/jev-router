# D071 — evidence-bound causal repair ownership

2026-10-11, updated 2026-10-12. This role implements the new causal repair module, contract and focused tests under [D071_PARALLEL](D071_PARALLEL.md). Root subsequently delegated shared executor integration to this role. Root owns planner/runner integration and every provider, Docker and ledger action. Historical candidates and evidence remain read-only. The purpose is to let an observed public assertion reach the relevant producer, representation and renderer owners, without silently granting every worker new writes.

## Implemented contract and integration

`buildAdaptiveCausalRepairScope` wraps the existing bound public-assertion scope. New assertion contract version 2 keeps the direct output path and adds explicit `causal_paths` with `path`, `role` and `rationale`. Roles are `producer`, `representation` and `renderer`. A current public assertion, checker manifest, environment, plan and artifact revision must agree before these paths can nominate current artifact owners. The causal paths are candidate hypotheses, not proof that each file is defective. Error-message text never grants a path or an owner.

The new scope retains legal direct choices and adds exact stage and connected-chain choices. Candidate `artifact_ids` grant writes; `read_artifact_ids` grant only inspection of the bound artifacts needed to examine the complete chain. The executor materializes extra reads from verified failure-round snapshots, separately from current declared DAG inputs. It does not copy extra files into a worker stage or add dependency edges. Original DAG outputs, selected-worker-only dispatch, byte/executable-mode carry-forward and complete public rechecks stay enforced. An unresolved ownership fallback alone cannot nominate every project worker.

`buildCausalRepairDecisionContext` and `buildCausalRepairWorkerContext` reuse artifact-repair-v2, preserve observed assertions and requirements, and attach the fixed English instructions from `docs/orchestration/contracts/adaptive-causal-repair.v1.json`. `loadCausalRepairContract()` exposes those instructions and the contract source hash to the caller. The worker context includes complete read-only upstream interfaces but cannot widen its candidate's write paths. Local evidence references are provenance only; the model cannot retrieve them. The live chooser calls `projectCausalChooserPacket` and sends readable JSON. The experimental dictionary codec remains in separate evidence and tests and is not applied to live requests. Short `decision_call_instructions` and `candidate_reference_template` point to `state.instructions` and `state.candidates`; neither asks Jev to decode a compressed dictionary. Semantic projection is recorded as `report.semantic_projection` (`lossless: false`), while `report.encoding.applied` is false. Controller-only omitted values and SHA alias occurrences can be restored with `restoreCausalChooserPacket`; they are not model retrieval tools.

The chooser retains full requirement text linked to observed failed assertions or the bound causal chain. Known unrelated implementation requirements and full interfaces remain in the selected worker packet and reconstructable controller evidence. Unknown or unresolved links keep all requirements. Only known noncausal worker profile rows may be omitted from the chooser; the controller preserves them. Current failure observations stay inline. A historical observation is represented as `same_as_current: {check_id, test_id, assertion_id}` only when its complete observation value and identity equal a current observation. A changed value, extra field, ambiguous identity or unknown observation remains literal. Restoration verifies the exact original state, including history; the readable references do not claim the failure has been resolved.

The controller supplies prior public failures, selected scopes and before/after artifact revisions. `buildCausalRepairHistory` records actual file hash/executable-mode changes, selected-but-unchanged artifacts, and persistent/resolved/new/unobserved assertion keys. A missing or not-reached assertion is not resolution. Source/catalog mismatches, writes outside the selected artifacts and discontinuous revision histories fail closed. History is observed evidence, not an instruction to repeat the previous patch. A new actual decision is required for each permitted repair round. The final successful round is persisted too.

## Caller API and evidence fields

- `buildAdaptiveCausalRepairScope({plan, failure, publicChecks, testRequirements, artifactBindings, sourceFiles, assertionContract, runtimeBinding, repairHistory})` returns `{candidates, analysis}`. Store `analysis` in `failure.repair_scope`. The assertion envelope is `{contract, source_text, source_path, sha256}` and must be version 2; all normal source/runtime/check/revision validation runs first.
- Each candidate has exact `task_ids`, `artifact_ids`, `read_artifact_ids`, `evidence_refs`, `reason` and `attribution_basis`. `analysis.causal` contains grouped public causal paths, unresolved/excluded reasons, binding hashes, sealed choice hashes and `repair_history`. These are candidate hypotheses, not execution traces or fault proof.
- `buildCausalRepairDecisionContext({planning, failure, candidates, artifactBindings, ...})` returns `{state, report}`. `buildCausalRepairWorkerContext({planning, failure, candidate, task, artifactBindings})` returns `{task, context, report}` with the narrowed task outputs/write scope and `context.required_read_artifact_ids`, `required_read_artifacts`, `causal_read_interfaces`, `causal_read_evidence` and `causal_read_basis`.
- `buildCausalRepairHistory({planning, artifactBindings, attempts})` consumes controller observations `{round_index, action, before_failure, after_failure, after_artifact_revisions, changed_files, status}`. The history entry index starts at zero for the first repair, while the runtime repair round starts at one. Full before/after failures remain in runtime evidence; the packet contains exact failure observations plus source/revision hashes and actual deltas.
- Enable the shared executor with `repairScopePolicy: 'public-causal-v1'` and `artifactRepairPolicy: 'causal-v1'` together. The execution callback receives `additional_read_sources: [{path, root, sha256}]`. Each source is checked against the prior verified manifest and revision immediately before dispatch; `root` is controller-side transport configuration, not model prompt content. Existing input and own-output paths are excluded from this overlay.
- `prepareRoundPlan({plan, round_index, selected_task_ids, selected_action, failure, repair_history}) -> {plan}` runs before each selected repair. Only `workers[].profile_id` for the selected implementation workers may change. Other DAG fields, task scopes, artifacts, IDs and unselected workers are compared to the original round plan and rejected if changed.
- After a validated profile change, `planning.plan.workers` reflects the actual round plan. For `execution_context.profile_policy: 'per_task_jev_selection'`, `worker_profiles` is also refreshed before building worker packets; a stale fixed-profile assumption is not presented as the actual selected profile. Fixed-profile execution context is unchanged.
- Runtime records `adaptive_causal_read_sources_verified`, `adaptive_causal_read_sources_rejected`, `adaptive_causal_repair_history_updated`, `adaptive_causal_repair_history_unavailable`, and repair profile preparation events. Final execution returns `repair_history`; each completed repaired round also records its current history. Known provider failures retain their terminal cause if no worker was started.
