# D073 — 실패별 기존 담당 추론과 로컬 입력 상한 해제

첫 두 조건 종료 후 [입력 v2 후속 프로토콜](../orchestration/D073_FOCUSED_OWNER_EXPERIMENT.md)을 같은 역할로 진행한다. 소스 동결 해제 전 원본4439개·실행소스270개 변경0을 확인했다. 새 두 조건은 기존 D071/D073 후보의 보존 수리이며 전체 초기 개발 반복이 아니다.

사용자 지시(2026-10-12): 실패별 담당 연결을 기존 담당을 추론하는 방식으로 구현하고, 토큰 한도 없이 진행한다. 목적은 실패 후 Jev 판단이 실제 수리 실행으로 이어지게 하는 것이다. D071/D072 원본은 보존한다.

## 역할과 소유권

- Root: manifest v8, `src/benchmark/adaptive-dag-runner.mjs`, `scripts/adaptive-dag-comparison.mjs`, 공유 상태/결정/실험 문서, source freeze, 실제 호출·독립 채점·최종 비교. 기존 CLI/모델/환경과 장부 확인도 root가 한다.
- `d067_budget`: 새 `adaptive-inferred-repair.mjs` 및 영어 질문 계약·집중 테스트, `src/orchestration/adaptive-dag-execution.mjs`의 추론된 담당→후보→실행 연결. 기존 causal 모듈 수정이 필요하면 변경 전 snapshot을 남긴다. 공개 실패·현재 소유권·산출물·의존성과 원문 요구를 근거로 추론하며 숨김 채점은 읽지 않는다.
- `d071_transport`: 새 v4 token admission과 계약·집중 테스트. 로컬 토큰 추정/repair 바이트 상한을 차단 조건에서 해제한다. 요청 schema, 공식 256000B, 신뢰된 stage, 모델/요청/정책 SHA, 불확실 결과 처리와 재시도0은 유지한다. D072 입력 검사 CLI에 명시 v3/v4 선택을 추가하되 기존 기록은 변경하지 않는다.
- `d067_runner`: 프로필 선택의 로컬 48000B/토큰 guard를 새 opt-in 조건에서 해제하고 v4 admission을 주입할 수 있도록 연결한다. 기존 v1/D071 기본 행동과 계약은 보존한다. 새 질문·작업자 profile 선택/실제 실행 검증은 기존 경로를 유지한다.
- `d067_review`: `preserved-artifact-repair-runner.mjs`와 해당 CLI/집중 테스트. D071 jev_profile 실패 후보를 별도 디렉터리에서 읽기 전용 상속하고 새 담당 추론/공개 수리를 실행할 준비를 한다. 담당 추론 입력과 미변경 산출물 상속 검증에 집중하며 provider/Docker 실행은 root에게 맡긴다.
- `d068_failure`: 별도 D073 입력/단계/회계 분석 도구와 역할 기록. 이전 D071 분석기는 보존하고 실패별 담당 질문 수·실제 POST·선택·수리worker·검사·총시간/토큰/공식환산을 구분한다. 새 개발과 보존 수리의 시작점을 합쳐 효율을 주장하지 않는다.
- `d071_review`: 구현 후 독립 검토·source pin·입력 계약 검증. 원시 코드/fixture를 검토하되 개발 담당 파일은 수정하지 않는다. 숨김 검사 정보는 계획·작업자 입력으로 전달하지 않는다.
- `d067_skills`: 단일 스킬 관리. 필요성을 검토해 추론 소유권과 확정 결함/실제 수리 결과의 구분 및 사용자 상한 해제 경계를 문서에 남긴다. 전역 설치/새 스킬/추가 유료 요청은 하지 않는다.

## 공통 계약

질문은 고정 영어 문서에서 읽고 실패·담당·선택 후보를 명시한다. Jev는 기존 작업자/산출물 allowlist에서 담당을 추론하고 선택값은 검증 후 실행에 연결한다. 추론 결과를 실제 결함 위치 확정으로 부르지 않는다. 판단 불가/모호함을 남기며 기존 소유권이나 쓰기 경로를 모델 임의로 확대하지 않는다.

사용자 로컬 토큰 예산/추정 상한은 null 또는 비차단 관측으로 둔다. 제공업체의 실제 문맥·body 제한은 제거할 수 없으며 오류를 보존한다. 부족한 근거를 임의 잘라 통과시키지 않는다. 재시도0과 기존 장부 ID·사용량·정산은 유지한다.

역할 문서에는 수정 파일·검증 명령·오류·남은 작업·인계 API를 남긴다. 파일 소유권이 겹치면 root와 조율한다. 문맥 압박 시 역할 문서에 인계한 뒤 쓰기를 멈춘다. root만 실제 호출/도커/장부/독립 채점을 실행한다.
