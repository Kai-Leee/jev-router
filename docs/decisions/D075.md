# D075 — 강제 전송 검사·실패 복구 구현과 보존 후보 실측

사용자는 사전 검사를 실제 전송 전에 강제 연결하고 실패 복구를 병렬 구현한 후, 기존 실패 후보를 다시 실행해 완료·시간·토큰·비용을 비교하도록 요청했다. 이 요청 및 기존 유료 실행·별도 Opus 모니터 승인 범위에서 진행했다. `complete`는 지원 경로 구현과 요청한 실험·보고의 종료이며 제품 성공이나 모든 복구 분기 구현 완료를 뜻하지 않는다.

[결과와 재현 명령](../orchestration/D075_RESULTS.md) · [실행 계약](../orchestration/D075_FORCED_PREFLIGHT_AND_RECOVERY.md) · [병렬 역할](../agents/D075_PARALLEL.md) · [전체 숫자](../../benchmark-runs/d075-root-01/final-summary.json).

동일79/93 출발점에서 최신88/93·60/63은 이전91/93·61/63보다 낮다. 공식 환산 알려진 소계는3.6566% 줄었지만 채점까지 관측 시간은3.8628% 늘었다. 새 원인 근거 수집 후 owner 입력 한도에서 다시 멈췄으므로 완료 효율 향상을 입증하지 못했다. 첫 profile 전달 결함·마지막 후보 포인터 누락·모니터 계약 누락과 수정 전후 근거를 보존했다.
