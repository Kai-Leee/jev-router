# Jev가 실행 DAG를 만드는 과정 — D070 인터랙티브 설명

[HTML 열기](index.html) · [전체 화면](screenshots/dag-full.jpg) · [검증 기록](verification.json) · [출처 해시](provenance.json)

2026-10-11 현재 코드와 D070의 보존된 실제 요청·선택·영수증을 연결한 로컬 설명 자료다. 실시간 실행 대시보드가 아니며, 버튼을 눌러도 모델을 호출하거나 원본 실험을 수정하지 않는다. HTML 하나에 CSS·JavaScript·데이터가 포함되어 있다.

## 읽는 순서

1. **흐름 따라가기**: 원문/catalog → 분할 개수 → 단위 배정 → 재귀 → 관계 질문 → DAG 확정 → 병렬 실행 → 공개 실패 수리. 각 단계에서 누가 결정하고 무엇을 전달하는지, 고정 영어 질문과 실제 답이 다음 동작에 어떻게 연결되는지 확인한다.
2. **작업 트리 ↔ DAG**: 부모·자식 분해 트리와 생산자·소비자 실행 의존성을 전환한다. 노드를 누르면 담당 단위·산출물·파일·선행 작업과 초기 구현 영수증의 시간·토큰·환산 비용이 열린다. 재생은 실제 모델 호출 구간만 표시하며, 응답 완료가 파일 검증 완료를 의미하지 않는다.
3. **실제 Jev 요청**: 저장된 POST 50개(분할 개수 13, 배정 33, 관계 배치 2, 수리 2)를 검색한다. 관계 배치는 32+13개의 질문을 포함한다. 별도 로컬 선택 18개는 POST가 아니다. 요청 본문 전체와 응답의 model/type/choice/usage 발췌, 입력 필드, 선택→실행 규칙을 볼 수 있다.
4. **검증과 현재 한계**: 정해진 catalog 범위, 고정 작업자 프로필, 아직 없는 초기 시간 예측, 수리 후보의 누락과 추가 공개 진단 실패를 표시한다.

## 현재 구조의 경계

- Claude가 원문에서 준비한 동일 catalog를 D066 기록에서 재사용했다. 이 실행에서 새 catalog 준비 호출은 없었다. Jev는 주어진 단위 내부의 새 작업이나 파일을 자유 서술로 만들지 않는다.
- 실행기가 고정 질문 문서와 허용 후보를 만든다. Jev의 `choice`를 허용 목록에 대조한 뒤 분할·배정·관계·수리 핸들러에 연결한다. 후보가 하나면 로컬 처리한다.
- 분해 트리는 17노드이고 최종 구현 leaf는 10개다. 실행 DAG는 구현 10노드와 공개 검사 1노드다. Jev가 택한 구현 간선 8개와 모든 산출물을 읽는 검증 간선을 구분한다.
- 최대 leaf 허용 수 30과 실제 동시 실행 슬롯 2는 다른 값이다. 이번 작업자 모델은 Opus 5.5 medium으로 고정됐다. 초기 예상 시간이 없어 임계 경로 시간은 `null`이며, 이 경우 실행 우선순위는 원래 task 순서다.
- 원래 공개 85/85·독립 63/63을 통과했어도 추가 description 진단은 새 후보 0/8, 기존 Claude와 D069는 각각 8/8이었다. 동일 품질 목표 달성으로 확대하지 않는다. 자세한 결과는 [D070 품질 검토](../../orchestration/D070_QUALITY_REVIEW.md)에 있다.

## 재생성·로컬 실행

저장소 루트에서 다음을 실행한다. `benchmark-runs/`의 로컬 원본이 있어야 재생성할 수 있다. 이미 생성한 `index.html`을 읽는 데는 원본 폴더가 필요 없다.

```sh
node --check scripts/build-dag-explorer.mjs
node scripts/build-dag-explorer.mjs
python3 -m http.server 56751 --bind 127.0.0.1 --directory docs/visualizations/jev-dag-explorer
```

포트가 사용 중이면 기존 서버를 종료하지 말고 다른 빈 포트를 고른다. 이번 표시용 서버는 `http://127.0.0.1:56751/`에서 이 결과물 폴더만 제공한다. `index.html`을 직접 여는 방법도 있으나 이번 브라우저 검증은 localhost에서 진행했다.

빌더는 9개 관련 런타임 파일의 현재 SHA-256을 D070 실행 당시 pin과 비교하고, 50개 요청을 이벤트·영수증에, 응답 선택값을 실제 선택 이벤트에 연결한다. [provenance.json](provenance.json)에는 사용한 267개 출처와 HTML 해시가 있다. 전체 D070 launch source 242개도 종료 시 다시 대조했다.

## 이번 검증

Codex in-app browser에서 기본 화면, 단계 이동, 트리/실행 DAG 전환, leaf 선택과 파일 상세, 검증 노드 표시, 실제 모델 구간 재생·일시정지, 관계 선택 예시, 요청 필터/검색/빈 상태, 요청·응답·입력 필드 보기, 로컬 선택, 실패 진단, 근거 창/Escape/포커스 복귀를 확인했다. 데스크톱 1422×800의 문서 전체 가로 넘침은 0px였고, 관측한 콘솔 warning/error는 없었다. 캡처는 [DAG 화면](screenshots/dag-desktop.jpg)과 [전체 화면](screenshots/dag-full.jpg)에 남겼다.

제작 중 관계선이 무관한 중간 노드를 통과해 보이는 배치를 발견해 우회 경로로 수정했다. 필터를 바꿔도 이전 요청 상세가 남는 결함은 첫 일치 요청 선택/빈 상태 처리로 수정했다. 선택하지 않은 노드의 글자가 너무 흐린 문제도 조정했다. 기존 실험 실패를 바꾸거나 숨기지 않았다.

모바일 크기·다른 브라우저·`file://`·OS 클립보드 복사·브라우저 JSON 다운로드는 별도 검증하지 않았다. 설명 자료만 추가했으므로 전체 런타임 회귀와 새로운 벤치마크/유료 추론은 실행하지 않았다.

## 데이터·부수 효과

인증 헤더·API 키는 HTML에 포함하지 않는다. 빌더는 `.env`를 읽지 않으며, 페이지의 CSP는 `connect-src 'none'`이다. 모델 API 호출 기능과 외부 스크립트가 없다. 실제 청구 미상과 공식 단가 환산을 구분한다.

기존 코드·실험 원본은 보존했다. 새 빌더·HTML·검증·이미지 및 문서 링크는 미커밋 상태이고 표시용 localhost 서버가 남아 있다. 기존 8787 대시보드 통합, 배포, commit/push, 새 성능 비교는 이번 변경에 포함하지 않았다.
